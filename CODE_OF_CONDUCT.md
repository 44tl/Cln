# Code of Conduct

## My Commitment

I'm committed to a welcoming, inclusive, and respectful environment for everyone who contributes to this project. I value clear communication and thoughtful decision-making.

## Expected Behavior

- **Explain your reasoning**: When submitting changes, clearly describe why you made the change and why you believe your approach is better than the existing implementation.
- **Provide context**: Help me understand the problem you're solving, the constraints you're working within, and the tradeoffs you considered.
- **Be constructive**: Offer feedback that helps improve the work, not just critique it.
- **Respect differences**: Everyone comes from different backgrounds and has different expertise. Be patient and respectful when discussing approaches.

## Unacceptable Behavior

- Submitting changes without explanation or clear reasoning
- Dismissing others' approaches without providing constructive alternatives
- Making changes that break existing functionality without documenting why
- Ignoring feedback or refusing to explain your decisions

## Why I Require Explanations

Every contribution should answer three questions:

1. **What did you change?** – The code itself shows this, but a clear summary helps.

2. **Why did you change it?** – This is critical. Understanding the motivation behind a change helps me assess if the change achieves the intended goal and avoid regressions from well-intentioned but misguided fixes.

3. **Why is this approach better?** – Consider alternatives and explain why your solution is preferable:
   - Performance implications
   - Maintainability
   - Compatibility
   - Tradeoffs compared to other approaches

Good commit messages and PR descriptions are not bureaucratic overhead—they are documentation of the thinking behind the code.

## AI Assistance

You can use AI to help write code, but you must understand what the AI produces. AI makes mistakes, especially with security-related code. Before submitting AI-generated changes:

- **Verify the code works** – Test it. Don't assume AI got it right.
- **Understand the logic** – If you can't explain what the code does, don't submit it.
- **Security knowledge required** – This is a security scanner. You need knowledge of:
  - How viruses and malware work
  - Common attack vectors and evasion techniques
  - Windows internals, PE files, archives, scripts
  - Why certain patterns are suspicious

## Reporting

If you observe violations of this code of conduct, please report them by opening an issue.

## Enforcement

Violations may result in removal from contributing privileges. The goal is not punishment, but maintaining a culture of thoughtful, explainable contribution.
